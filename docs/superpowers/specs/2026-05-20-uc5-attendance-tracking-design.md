# UC5: 参加者把握・出欠管理設計書

**作成日:** 2026-05-20  
**バージョン:** v2  
**ステータス:** 設計確定

---

## 1. 概要

UC5 は、**イベント主催者が自分のイベント参加者の出欠を管理する機能** です。

主催者はイベント詳細ページから参加者一覧にアクセスし、当日の開始時刻から参加者の出欠をリアルタイムで記録できます。

---

## 2. ビジネス要件（PDF より）

### 満たすべきこと
- 自分が立てたイベントの参加者一覧が見られる
- 当日の出欠（参加した／しなかった）を記録できる
- 後でフォローアップできる程度の参加者情報が見られる

### 設計時の論点と決定
- **個人情報の開示範囲**
  - 決定：名前のみ表示。メールアドレスは非表示
  - 理由：参加者が安心して登録でき、主催者や他者からの直接連絡を防止

- **出欠記録のタイミング**
  - 決定：イベント開始時刻から（当日の開始頃に記録開始）
  - 理由：遅刻者にも対応しつつ、解散時の煩雑さを避ける

- **キャンセル済み参加者の扱い**
  - 決定：イベント詳細ページで「参加者」「キャンセル一覧」の2セクションに分離
  - 理由：出欠管理の焦点を絞りつつ、キャンセル履歴を参照可能に
  - 再申し込み時の動作：キャンセル一覧から自動削除、参加者一覧に移動

## 3. 技術設計

### 3.1 データベーススキーマ

#### テーブル変更：`event_attendances`

```sql
ALTER TABLE event_attendances ADD COLUMN attended_at TIMESTAMP NULL;
```

| カラム | 型 | NULL許可 | デフォルト | 説明 |
|---|---|---|---|---|
| `attended_at` | TIMESTAMP | YES | NULL | 主催者が出欠を記録した日時。NULL = 未記録（=未参加） |

**状態遷移：**
```
参加申し込み時:
  attended_at = NULL
  （未参加状態がデフォルト）

主催者が「参加」を記録:
  attended_at = CURRENT_TIMESTAMP
  （参加確定）

間違えた場合「未参加」に戻す:
  attended_at = NULL
  （初期状態に戻す）
```

**マイグレーション時の考慮：**
- 既存の参加レコードには全て NULL が設定される
- v2 本番デプロイ前にステージング環境で試行必須

### 3.2 ルート＆API

#### 新規エンドポイント

```
PATCH /events/{event}/attendances/{attendance}
```

**リクエスト：**
```json
{
  "attended_at": "2026-05-20T14:00:00Z" または null
}
```

**レスポンス：**
```json
{
  "id": 1,
  "event_id": 1,
  "user_id": 2,
  "attended_at": "2026-05-20T14:00:00Z",
  "created_at": "2026-05-20T10:00:00Z"
}
```

**エラーレスポンス：**
- 403 Forbidden：主催者でない場合
- 404 Not Found：参加レコードが存在しない場合

```

│ イベント詳細                             │

│ ▶ 参加者                                │

│   │ 参加 [✓]  未参加 [ ]            │  │
│   └─────────────────────────────────┘  │
│                                         │
│ ▶ キャンセル一覧（読み取り専用）       │
│   ・キャンセル済みの参加者を表示        │
└─────────────────────────────────────────┘
```

#### 出欠記録の UI インタラクション

**初期状態（attended_at = NULL）：**
- 「未参加」ボタンがデフォルト選択状態
- 「参加」ボタンは未選択

**参加者が到着したとき：**
1. 「参加」ボタンをクリック
2. attended_at = CURRENT_TIMESTAMP に更新
3. UI が即座に「参加」ボタンをハイライト

**間違えた場合：**
1. 「未参加」ボタンをクリック
2. attended_at = NULL に戻す
3. UI が「未参加」に戻る

### 3.4 認可（Authorization）

#### EventPolicy の拡張

```php
// app/Policies/EventPolicy.php

public function updateAttendance(User $user, Event $event): bool
{
    return $user->id === $event->user_id;
}
```

**Blade テンプレートでの条件表示：**
```blade
@can('updateAttendance', $event)
    <!-- 出欠管理セクション -->
@endcan
```

**コントローラー側での検証：**
```php
$this->authorize('updateAttendance', $event);
```

## 5. マイグレーション戦略

本番環境での無停止デプロイを前提とします。

### ステップ
1. **ステージング環境で試行**
   - マイグレーション実行
   - 既存データの確認（全て attended_at = NULL）
   - 動作テスト（トグル操作、認可チェック）

2. **本番デプロイ**
   - コードデプロイ（新しい機能 + マイグレーション）
   - マイグレーション実行（`php artisan migrate --force`）

3. **ロールバック手順**
   - 問題発生時：`php artisan migrate:rollback`
   - キー：マイグレーション前の状態に戻る

### 後方互換性
- 新しいカラムは NULL デフォルトなので、既存コードで新カラムへのアクセスがなければ互換性問題なし
- v1 の画面（参加者一覧表示）は影響なし

---

## 6. 既知の制約

- **参加記録の履歴を残さない**
  - 出欠が「参加」→「未参加」→「参加」と変わった場合、最終状態のみを保持
  - 完全な監査ログが必要な場合は、将来的に別テーブルを導入

- **出欠記録者の追跡なし**
  - 誰がいつ出欠を記録したかは記録していない
  - 必要に応じて v3 以降で拡張可能

## 8. 設計判断の根拠まとめ

| 項目 | 決定 | 根拠 |
|---|---|---|
| 表示情報 | 名前のみ | プライバシー保護。メール開示は参加者不安 |
| 記録タイミング | イベント開始時刻から | 遅刻者対応 + 解散時の煩雑さ回避 |
| キャンセル扱い | 別セクション表示 | 出欠管理の焦点を絞りつつ、履歴参照可能 |
| スキーマ | attended_at のみ | シンプル。NULL = 未参加（デフォルト） |
| UI | トグルボタン | クリック数最小化、シンプルな操作 |
| 認可 | EventPolicy 拡張 | 既存パターンの踏襲、実装シンプル |
