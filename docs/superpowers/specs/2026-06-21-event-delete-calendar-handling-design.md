# イベント削除時の Google カレンダー対処方針 設計

## 概要

運営がイベントを削除した際、参加者の Google カレンダーに登録済みのイベントをどう扱うかの方針を検討する。

---

## 現状

| 操作 | Google カレンダー対応 |
|------|----------------------|
| 参加者自身がキャンセル | 自動削除済み（`EventAttendanceService::cancelAttendance`） |
| 運営がイベントを削除 | **未対応**（メール通知のみ） |

運営削除時は `AdminService::deleteEvent` でメール通知のみ行っており、`google_calendar_event_id` を持つ参加者のカレンダーは放置される。

---

## 対応案

### 案1: 何もしない（現状維持）

参加者が受け取るメール通知を頼りに手動で対処してもらう。

**メリット**
- 実装コスト 0

**デメリット**
- カレンダーに「幻のイベント」が残り続ける
- メール通知を見逃したユーザーが当日会場へ向かう可能性がある

---

### 案2: 削除時に Google カレンダーからも自動削除

`AdminService::deleteEvent` 内で `GoogleCalendarService::deleteEvent` を参加者全員分呼び出す。

**メリット**
- ユーザーの手間が不要
- カレンダーが自動でクリーンになる

**デメリット**
- API 呼び出しが参加者数分発生し、失敗しても処理全体を止められない（ログ記録のみ）
- `google_calendar_event_id` が `null`（カレンダー未連携 / 同期失敗）の参加者には処理できない
- Google API のレート制限・障害時に削除が漏れる

---

### 案3: Google カレンダーのイベントをキャンセル状態に更新

削除ではなく Google Calendar API でタイトルを「【中止】○○」に書き換え、ステータスを `cancelled` に変更する。

**メリット**
- ユーザーのカレンダーに「中止になった」という記録が残る
- 削除より状況が伝わりやすい

**デメリット**
- 実装が案2より複雑（イベント更新 API の利用）
- カレンダーアプリによって表示が異なり、取り消し線が出るとは限らない

---

### 案4: メール通知に手動削除の案内を追加

既存の `AdminEventDeletedMail` に「Google カレンダーからも手動で削除してください」の一文を加える。

**メリット**
- 実装コストが低い
- ユーザーが主体的に対応できる

**デメリット**
- メールを見逃すと対処されない
- UX としては不親切

---

## 比較表

| 案 | 実装コスト | ユーザー体験 | カレンダー連携なし参加者への対応 | 失敗リスク |
|----|-----------|-------------|-------------------------------|-----------|
| 案1: 何もしない | なし | 悪い | 影響なし | なし |
| 案2: 自動削除 | 中 | 良い | 対応不可（スキップ） | API障害時に削除漏れ |
| 案3: キャンセル状態に更新 | 高 | 良い | 対応不可（スキップ） | API障害時に更新漏れ |
| 案4: メールで案内 | 低 | 普通 | 影響なし | メール見逃し |

---

## 推奨

**案2（自動削除）＋ 案4（メール案内）の組み合わせ**

- `google_calendar_event_id` がある参加者に対して自動削除を試みる
- 失敗しても処理全体は止めない（`Log::warning` のみ）
- メールに「カレンダーからも削除されました / されていない場合は手動で削除してください」と添える

これにより大多数のユーザーは自動で対処されつつ、未連携ユーザーや失敗ケースもメールでフォローできる。
