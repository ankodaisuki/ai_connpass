# アーキテクチャ決定記録（ADR）

このディレクトリは、**ユーザーから見える動作（表側仕様）が変わる設計判断**を、バージョン単位で記録します。意思決定者（上司・企画）と後続の保守メンバーが、判断の経緯とトレードオフを追跡できるようにすることが目的です。

## 何をADRに残すか

- **残す:** ユーザーから見える動作・表示・できることが変わる判断（例: 合同主催者を公開ページに表示するか、オーナー退会時にイベントが残るか）。
- **残さない:** 裏側の実装選択（テーブル設計・クラス構成・移行手順など）。これらは `docs/superpowers/plans/` の実装計画に書きます。

## フォーマット（MADR ベース）

各ADRは次の構成で書きます。

1. 背景と課題
2. 決定ドライバー（判断基準）
3. 検討した選択肢
4. 各案のメリット・デメリット
5. 推奨と理由（Proposed 時のたたき台。決定は意思決定者に委ねる）
6. 決定（承認時に記入）
7. 影響・結果

**ステータス運用:** `Proposed`（提案・レビュー待ち）→ `Accepted`（採用）→ 必要なら `Superseded by ADR-XXXX`（後継に置換）。

**配置・命名:** `docs/adr/v{N}/{4桁連番}-{slug}.md`
